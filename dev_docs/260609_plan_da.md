# GUIへのDeterministic Annealing 実装プラン

## 1. 目的

EMPeaks GUI に `deterministic_annealing` フィッティング手法を追加し、
それに伴い必要なパラメータ（`Dirichlet_alpha`）をユーザーが設定できるようにする。

---

## 2. 前提知識：メソッドの仕様確認

### `deterministic_annealing` のシグネチャ

```python
def deterministic_annealing(self, x, intensity,
                             max_iter=3000, r_eps=1e-9,
                             temp0=3, n_temp=5, stdout=False):
```

- `temp0`: 初期温度の指数（基準値 3）
- `n_temp`: アニーリングステージ数（基準値 5）
- 内部で `self.fit(..., method='adapted_em')` を `n_temp` 回呼ぶ

### 返値の構造

```python
info = {
    'LL':         float,        # 最終ステージのLL
    'RMSE':       float,
    'total_time': float,
    'total_iter': int,
    'LL_hist':    np.ndarray,   # shape (n_temp,)
    'RMSE_hist':  np.ndarray,   # shape (n_temp,)
    'time_hist':  np.ndarray,   # shape (n_temp,)
    'iter_hist':  np.ndarray,   # shape (n_temp,)
}
```

**注意**: `index_best` キーが存在しない。`fitting_board_constructor` は `info['index_best']` を参照するため、
`_wrap_single_run_info` では対応できず **専用ラッパーが必要**。

### `Dirichlet_alpha` の役割

```python
# _em_core.py の EM ステップ
self.pi = (N_k + self.Dirichlet_alpha - 1) / np.sum(N_k + self.Dirichlet_alpha - 1)
```

- `alpha = 1.0`（デフォルト）: 通常EM と等価、スパース化なし
- `0 < alpha < 1`: スパース化を促進（不要なコンポーネントを 0 に押し込む）
- `alpha <= 0`: 数値的に不正（対数に負値が入る可能性）

#### 3-A-2. `run()` に DA 分岐を追加

```python
elif fitting_method == 'deterministic_annealing':
    alpha = st.session_state.get('DirichletAlpha', 1.0)
    model_instance.Dirichlet_alpha = np.ones(model_instance.K_all) * alpha
    run_info = model_instance.deterministic_annealing(
        x_arr, y_arr,
        max_iter=st.session_state['MaxIteration'],
        r_eps=st.session_state['Threshold'],
    )
    out_info = _wrap_da_info(run_info)
```

#### 3-A-3. `_wrap_da_info()` を追加

```python
def _wrap_da_info(run_info):
    """deterministic_annealing の返値を fitting_board_constructor 互換に変換"""
    return {
        'index_best': len(run_info['LL_hist']) - 1,   # 最終ステージが最良
        'LL_hist':    run_info['LL_hist'],
        'RMSE_hist':  run_info['RMSE_hist'],
        'time_hist':  run_info['time_hist'],
        'iter_hist':  run_info['iter_hist'],
    }
```

`_wrap_single_run_info` は `LL_hist` をスカラーから長さ1配列に変換するものであり DA には転用できない。

### B. `gui/module/model_constructor.py`

```python
FITTING_METHOD_STANDARD = ['sampling', 'deterministic_annealing']
FITTING_METHOD_TSDC     = ['sampling', 'leastsq', 'leastsq_tau0', 'l2_div']
# TSDCへの DA 追加は §4 参照
```

#### 3-B-2. DA 選択時に `Dirichlet_alpha` 入力欄を表示

既存の TSDC パラメータブロックと同じパターンで、メソッド選択の直後に配置する:

```python
if st.session_state['FittingMethod'] == 'deterministic_annealing':
    st.sidebar.subheader(t("da_parameters"))
    alpha = st.sidebar.number_input(
        t("dirichlet_alpha"),
        min_value=0.01,
        max_value=2.0,
        step=0.1,
        format="%.2f",
        key='DirichletAlpha',
    )
    if alpha <= 0:
        st.sidebar.error(t("da_alpha_error"))
        st.session_state['TriggerOptimization'] = False   # 実行をブロック
    elif alpha >= 1.0:
        st.sidebar.warning(t("da_alpha_warning"))
```

`min_value=0.01` を設定することで `alpha <= 0` を入力段階でブロックし、
`st.sidebar.error` によるソフトブロックと二重に防護する。

## 4. TSDC への DA 対応について

現時点では `FITTING_METHOD_TSDC` へ `'deterministic_annealing'` を**追加しない**。

理由:
- DA は内部で `self.fit(..., method='adapted_em')` を呼ぶ
- TSDC の `adapted_em` は同モデル固有の Rust EM ループを使用しており動作上の問題はないが、
  温度を `intensity / temp` でスケールする操作が TSDC の物理的解釈と整合するか未検証
- 分光データ（XPS/PES 等）向けの DA の有効性は確立されているが TSDC での効果は不明

将来、TSDC での DA 有効性が確認されたタイミングで `FITTING_METHOD_TSDC` に追加する。

---

## 5. スコープ外（v1 では対応しない）

| 項目 | 理由 |
|---|---|
| `temp0` / `n_temp` の GUI 露出 | デフォルト値（3 / 5）で十分。過度な UI 複雑化を避ける |
| DA + b_spline バックグラウンドの組み合わせ検証 | 機能上は動作するはずだが、スパース化の解釈が複雑になる |
| DA 進行中のステージごとの LL 推移表示 | `fitting_board_constructor` の改修が必要になる |

## 7. 検証計画

- `Dirichlet_alpha = 1.0`（スパース化なし）で DA 実行 → `sampling` と同等の結果が出ること
- `Dirichlet_alpha = 0.5` で DA 実行 → 不要コンポーネントの `pi` が 0 に収束すること
- `alpha <= 0` 入力時に START Optimization がブロックされること
- `_wrap_da_info` の `index_best` が正しく `n_temp - 1` を指すこと
- b_spline / uniform / none 各背景との組み合わせで例外が出ないこと
